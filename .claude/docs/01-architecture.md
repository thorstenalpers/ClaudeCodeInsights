# Architecture

## Core principle

Rust owns the data and every decision about it. The frontend renders and asks
questions; it holds no domain logic and no rates.

| Responsibility                          | Rust | Svelte |
| --------------------------------------- | ---- | ------ |
| Window, WebView lifecycle, splash       | ✓    |        |
| Reading transcripts, SQLite             | ✓    |        |
| Paging, sorting, filtering, aggregation | ✓    |        |
| Cost calculation                        | ✓    |        |
| Everything visible                      |      | ✓      |
| Navigation, view state                  |      | ✓      |

## Layout

```
/                       SvelteKit at the repository root (Tauri convention)
├── static/             served as-is: favicon, splashscreen.html
├── src/
│   ├── app.html        the shell SvelteKit fills in
│   ├── routes/
│   │   ├── +layout.ts      ssr off, prerender off — a client-routed SPA
│   │   ├── +layout.svelte  rail, header, splash handshake
│   │   ├── +page.svelte     overview
│   │   └── sessions/[id]/   the transcript of one session
│   └── lib/
│       ├── ipc.svelte.ts   the only module that touches `invoke`
│       ├── api.ts          typed wrappers per command
│       ├── pages.ts        the rail: href, label, icon
│       ├── nav.svelte.ts   the detail label the URL cannot carry
│       ├── scan.svelte.ts  scan state, fed by backend events
│       ├── theme.svelte.ts mode, colour preset, brand overrides
│       └── components/ui/  generated by shadcn-svelte — do not edit
└── src-tauri/src/
    ├── lib.rs          builder, splash handshake, command registration
    ├── commands/       one module per domain: scan, sessions, projects, overview
    ├── error.rs        the one error type; serialises as { kind, message }
    ├── state.rs        everything registered with .manage()
    ├── paths.rs        every path the app reads or writes
    ├── projects.rs     ~/.claude.json registrations: list, delete transcripts,
    │                   edit settings — writes go backup-first, then atomic
    ├── assistant/      where an answer comes from: the local CLI, or a hosted
    │                   model called from here so the key stays out of the window
    ├── storage/        connection, pragmas, forward-only migrations
    ├── ingest/         transcript reading and the incremental scan
    └── analysis/       categories, activity, session queries, transcript replay
```

## Startup

The main window starts hidden and a separate splash window shows first. The
splash is plain HTML with inline CSS and **no module script**: its whole purpose
is to be on screen before the app bundle has loaded, so anything it waits for
defeats it.

Both halves report through `set_complete`, and the window is revealed when both
have. Both must go through `mark_ready()` — an earlier version let the backend
set its flag directly, so whichever half finished second never re-checked the
condition and a fully started app sat on the splash until the timeout.

The frontend reports only after a real painted frame. It races two nested
`requestAnimationFrame` calls against a 500 ms timer, because a window that is
not compositing has its animation frames throttled to a standstill — and this
window starts hidden. A 15 s timeout in Rust reveals the window regardless: a
slow UI is better than one the user cannot reach.

## Page state

The router owns which page is showing, so a page is destroyed when it is left
and rebuilt when it is entered. State that has to survive navigation therefore
belongs in a store, not in a component: `scan.svelte.ts` keeps a running scan
reporting across pages, and `theme.svelte.ts` keeps the appearance.

This replaced a keep-alive page host that kept every visited page mounted and
only toggled `hidden`, which preserved scroll position and table sorting for
free. Routing costs that; the trade was made deliberately for URLs, real links
and a structure the framework understands. Anything worth keeping now has to be
lifted into a store or the URL on purpose.

Session detail is its own route, `/sessions/[id]`. The sessions table hands the
topic over through `nav.detailLabel` so the header can show a name instead of a
UUID while the transcript is still loading.

## Theming

Two independent axes on `<html>`: `mode-watcher` toggles `.dark`, and a colour
preset class overrides only the accent-carrying tokens. Both sit on the same
element, so dark variants are written `.dark.theme-x`.

Every theme change goes through `applyThemeChange()`, which suppresses
transitions across the swap. Chromium keeps the **old** colour indefinitely on
an element whose colour comes from a CSS custom property when that property
changes on an ancestor and the element has a transition covering it. shadcn's
Button has `transition-all`; without the guard a theme switch leaves buttons in
the previous theme. Verified: still stale after 3 s and a forced repaint.
